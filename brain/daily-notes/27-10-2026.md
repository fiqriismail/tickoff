- Asked: start #14 (already assigned to fiqriismail); branched from up-to-date `main`.

Tests: `SettingsStoreTests`, `SettingsModelTests`, `ThemeTests` (42 tests pass in total). Removed `Features/.gitkeep` and its empty pbxproj exception.
- Verified in the running app against a throwaway home with Rust-style settings (dark, orange, small, compact on, notes off): all controls showed them unchanged, and changing the text size persisted to the DB immediately.
- Worth knowing: `.dynamicTypeSize` does nothing on macOS, so text size is an explicit font scale (0.9 / 1.0 / 1.15, the Rust zoom factors) set as the root font. Views that set their own fixed text styles (`.caption` etc.) and native segmented controls don't follow it; later features should size text from the environment font (`.bold()`, `.font(.body)`-style relative tweaks) or add a scaled-font helper.
- Incident: hosted `xcodebuild test` launches the app, and the app opened the real `~/.hello_gui/tasks.db` (only added the additive `grdb_migrations` table; 3 tasks and 5 settings intact). Fixed: `AppModel.launch()` uses an in-memory DB when `XCTestConfigurationFilePath` is set. Verified the real DB checksum is unchanged across a full test run. Manual runs can be redirected with `CFFIXED_USER_HOME` (not `HOME`).
- `fatalError` only exists for an in-memory SQLite open failing, which means SQLite itself is unusable.
- Follow-up: added a `system` accent (new default) that follows the macOS accent colour live (`NSColor.controlAccentColor`); the five fixed colours stay as overrides and saved choices are unchanged. Dark mode already defaulted to System. Text size stays an app setting by the user's choice (macOS has no system text size to inherit). 43 tests pass.
